# WS2812B bring-up

## Board mapping

On `Music-Light-V3-221101`, continuity tracing confirms:

- 32 addressable RGB LEDs;
- WS2812B-compatible protocol;
- data signal on ST17H66B **P34 / TSSOP-16 pin 1**.

## Selected transport: SPI1 SDO

For the first hardware bring-up, the repository uses SPI encoding rather than CPU-cycle bit-banging.

Reasons:

- PHY6222/ST17H66B platform references expose P34 as an SPI1 transmit/SDO-capable pin;
- public Tuya PHY6222 addressable-light examples use SPI as the WS2812 transport;
- SPI gives deterministic wire timing independent of C instruction scheduling;
- the same approach can later be moved to DMA if interrupt-free transmission becomes important.

Technical references:

- Tuya PHY6222 platform peripheral map:
  https://developer.tuya.com/en/docs/iot-device-dev/bluetooth_platform_ble_phy6222?id=Kcnreamkf9r1a
- Tuya addressable RGB strip example:
  https://developer.tuya.com/cn/docs/iot-device-dev/bluetooth_demo_ble_colorful_led_strip?id=Ketkqvmpnddfr

These are technical references only. Their source code is not copied into this repository.

## Encoding

SPI clock target: **2.4 MHz**. The backend reads the current peripheral clock from the ST17H66B ROM interface and selects the nearest valid even SPI divider, so the exact wire clock can differ slightly from 2.4 MHz and must be measured on hardware.

Each WS2812 data bit is expanded into three SPI bits:

| WS2812 bit | SPI symbol | High time at 2.4 MHz | Total bit time |
| --- | --- | ---: | ---: |
| 0 | `100` | ~0.417 us | 1.25 us |
| 1 | `110` | ~0.833 us | 1.25 us |

A logical RGB pixel is transmitted in WS2812 GRB order.

Each pixel therefore expands to:

- 24 WS2812 bits;
- 72 SPI bits;
- 9 SPI bytes.

For 32 LEDs the data payload is 288 SPI bytes.

The encoder appends 16 zero bytes. At 2.4 MHz this holds the line low for about 53.3 us, providing the reset/latch interval.

## First example

Build:

```sh
cmake --preset music-light-v3-221101-ws2812b-basic
cmake --build --preset music-light-v3-221101-ws2812b-basic
```

The example sends one static frame:

- LEDs 0..7: dim red;
- LEDs 8..15: dim green;
- LEDs 16..23: dim blue;
- LEDs 24..31: low-intensity white.

This pattern is deliberately simple so that channel order, pixel count and timing errors are obvious on first power-up.

## Validation level

The SPI symbol encoder is host-testable and build-validatable.

The ST17H66B SPI1 register backend is **experimental until measured on hardware**. Before treating it as validated, capture P34 with an oscilloscope or logic analyzer and verify:

- SPI bit rate is near 2.4 MHz;
- WS2812 bit period is near 1.25 us;
- zero/one high times are in tolerance;
- reset low interval exceeds 50 us.

Do not promote this backend to the normal firmware path until that measurement passes.
