# ST17H66B bring-up

## Current status

ST17H66B is the first MCU target for the light-bar firmware and is currently used by the canonical board target `Music-Light-V3-221101`.

Evidence level:

- Cortex-M0 / GNU Arm compilation path: source-confirmed
- linked ELF/HEX/BIN generation in this repository: build-pass in GitHub Actions
- generated BIN/HEX layout consistency: build-pass
- repository-owned BLE application protocol/host tests: build-pass
- GCC BLE implementation for the related PHY62x2/ST17H66B ecosystem: source-confirmed externally
- UART ROM programming path: source-confirmed externally
- `Music-Light-V3-221101` UART pads P9/P10: continuity-confirmed
- `Music-Light-V3-221101` microphone path P15/AIO_4: continuity-confirmed
- `Music-Light-V3-221101` WS2812B GPIO: tracing pending
- flash/run of this repository image on the board: pending hardware validation
- BLE radio/GATT operation from this repository: not yet implemented

The current linked image is an experimental bring-up image. Successful linking and artifact generation do not prove that its load/run layout is correct for the board.

## Relevant TSSOP-16 pins

Current bring-up-relevant pin functions:

| Package pin | Signal | Relevant function |
| ---: | --- | --- |
| 5 | P9 | GPIO; confirmed board ROM-UART TX |
| 6 | P10 | GPIO; confirmed board ROM-UART RX |
| 7 | P11 / AIO_0 | GPIO / ADC0 |
| 8 | P14 / AIO_3 | GPIO / ADC3 |
| 9 | P15 / AIO_4 | GPIO / ADC4 / MICBIAS; confirmed microphone path |
| 10 | P18 / AIO_7 | GPIO / ADC7 / PGA negative input |
| 11 | P20 / AIO_9 | GPIO / ADC9 / PGA positive input |

For the inspected `Music-Light-V3-221101`, continuity tracing has promoted P9, P10 and P15 from reference candidates to board facts. No LED GPIO is promoted until its trace is complete.

## Experimental memory/startup contract

The repository currently links a minimal image against a small SRAM-resident layout derived from public ST17H66B reverse-engineering evidence:

- image origin: `0x1FFF1838`
- RAM origin: `0x1FFF8000`
- RAM size: `0x2000`
- expected initial stack pointer: `0x1FFFA000`
- Cortex-M0 vector table and project-owned reset startup
- no vendor SDK or BLE stack linked

This layout is intentionally limited to early bring-up. A BLE-capable production image is expected to require the larger SRAM/XIP model used by PHY62xx-class firmware.

The loader and image relationship is documented in [FLASHING.md](FLASHING.md).

## Programming interface

Confirmed on `Music-Light-V3-221101`:

- package pin 5 / P9: target TX;
- package pin 6 / P10: target RX;
- USB-UART TX → target P10/RX;
- USB-UART RX ← target P9/TX;
- logic/power level: 3.3 V.

This removes the UART-pad ambiguity. The next ROM-UART operation is intentionally read-only until the original Flash backup is preserved.

## Microphone path

Continuity tracing confirms the board microphone network reaches package pin 9 / P15 / AIO_4.

The pin supports ADC4 and MICBIAS functionality. The exact analog configuration, bias network behavior and ADC sampling setup remain a hardware bring-up task; the repository does not yet claim a validated microphone acquisition path.

## GCC/BLE direction

BLE is mandatory for the project.

The repository owns and host-tests the transport-independent application control protocol. The radio/GATT backend remains separate.

The selected radio/backend direction remains a GCC-native build. Public PHY62x2/ST17H66B work demonstrates that the BLE host/controller stack can be compiled with `arm-none-eabi-gcc`; therefore Keil is not a project dependency by default.

The next BLE backend milestone is:

1. identify the minimum controller/host/startup/ROM interfaces required;
2. classify every candidate source file by provenance/license;
3. implement or import only material that can legally be distributed;
4. move from the small bring-up linker model to the validated SRAM/XIP model;
5. establish a minimal connectable GATT peripheral and bind it to the repository-owned control protocol.

Application-level control semantics are documented in [BLE.md](BLE.md).
