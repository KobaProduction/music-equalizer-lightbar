# ST17H66B bring-up

## Current status

ST17H66B is the first MCU target for the light-bar firmware.

Evidence level:

- Cortex-M0 / GNU Arm compilation path: source-confirmed
- GCC BLE implementation for the related PHY62x2/ST17H66B ecosystem: source-confirmed
- UART ROM programming path: source-confirmed
- This light-bar PCB pin mapping: not yet recorded in the repository
- Repository bootstrap build: build-pass in GitHub Actions
- Flash/run on this light-bar PCB: pending hardware validation

The current CI validation is compile-only. It does not prove the startup/linker contract, a flashable image, BLE operation, or hardware operation.

## Programming interface

Existing ST17H66B work uses the ROM UART boot path.

Known reference mapping at the SoC level:

- P09: target TX
- P10: target RX
- USB-UART TX -> target P10
- USB-UART RX <- target P09
- logic/power level: 3.3 V

The actual light-bar test pads must be mapped to the SoC pins before this becomes a board-level fact.

## BLE direction

BLE is a required capability for this project.

The preferred direction is a GCC-native build. The pvvx PHY62x2 codebase demonstrates compilation of BLE host/controller components with `arm-none-eabi-gcc`, so Keil is not treated as a required project toolchain.

Before code is imported, the exact source subset and licensing/provenance must be reviewed.

## Licensing constraint

The pvvx/THB2 license explicitly separates:

- permissively licensed source material;
- Phyplus SDK material subject to restrictive/confidential vendor terms.

This repository must not copy the restricted SDK portion under the project MIT license.

The next source-integration step is therefore to identify the minimal GCC BLE/startup/ROM-support subset, determine which files are permissively distributable, and only then vendor or reimplement what is required.
